Stages

Stages run top to bottom. A folder load adds one stage per .txt file, sorted by file name. In a batch file, each "### STAGE:" section becomes a stage.

Variables you can use in batches

Write these in the URLs and bodies of the operations. They are replaced before Preview and Run, so one batch file works on any site. Names are not case sensitive.

{{WebUrl}}
URL of the target site, e.g. https://tenant.sharepoint.com/sites/hr (no trailing slash).
{{WebServerRelativeUrl}}
The same without the host: /sites/hr (empty for a root site).
{{SiteUrl}}
URL of the site collection (differs from {{WebUrl}} on a subsite).
{{SiteServerRelativeUrl}}
The site collection without the host.
{{WebId}}
GUID of the target web, read from SharePoint when the batch runs.
{{ListId:Lists/crRequests}}
GUID of a list on the target site, without braces. Use it for lookup columns and anywhere a list ID is needed. After ListId: you can give the list title, its URL name (crDocumentVault), the URL relative to the site (Lists/crRequests), or a server-relative or full URL.
@{variables('x')?['Lists/crRequests']}
The Power Automate form of {{ListId:…}}, so existing flow bodies keep working.

Example: POST {{WebUrl}}/_api/web/lists or a lookup field with List="{{ListId:Lists/crRequests}}". Preview lists the web and list IDs it found.

          Site collection

          Open any page of the site collection in the active tab.

          Note Uses the classic search schema pages

          There is no API for the site collection search schema. This tab reads crawledproperty.aspx and sends the same request as its OK button. If Microsoft changes those pages, saving fails with an error and the row shows it.

          Mappings

          One crawled property and one managed property per row. Both fields suggest names and show what is already mapped. Paste rows from Excel (crawled ⇥ managed) into a crawled property field.

            Asks for confirmation, writes each crawled property and reads it back. Reindex the list or library afterwards so values appear.

            Request headers for SharePoint pages

            When on, the browser adds these headers whenever you open a SharePoint URL (https://<tenant>.sharepoint.com/…) in a tab whose path contains one of the path texts. It applies to all tabs of the browser. The default, Accept: application/json, returns JSON instead of XML. Add Accept-Language to read texts such as column names in another language. The Batch Runner is not affected: it sends the headers written in the batch.
